# 剪映自动剪辑产品方案对齐记录

> 文档状态：历史对齐记录；当前实现以《技术架构与选型》和《本机公网入库技术方案》为准
> 版本：v1.7
> 更新日期：2026-08-01
> 当前阶段：公网上传实现中

> 2026-08-01 变更：原先“付费 TURN 直接报错”的决定已废止。当前实现把 Cloudflare TURN 长期 Key/API Token 仅保存为 Worker Secret；每个上传会话经本机 HMAC 请求短期 ICE 凭据，长期凭据不会进入本机、手机或日志。下文的历史 TURN 拒绝记录仅用于追溯，不代表当前行为。

## 1. 产品目标

建设一套运行在用户本人 macOS 电脑上的本地智能剪辑系统：前端 Web、后端 Server、数据库、素材库、默认媒体 AI 和剪映执行器均运行在本机。用户可通过 iOS 或 Android 手机从公网向本机传输素材，在本机 Web 中管理项目、素材、长期风格和剪辑任务；系统分析用户素材及可选参考视频，并实际操作本机剪映专业版完成剪辑和导出。任何云端生成或推理能力均须单独配置与授权。

## 2. 已确认决策

以下内容已经确认，除非后续明确提出变更，否则作为后续设计和开发的约束。

### 2.1 默认内容形态

- 默认制作 Vlog，不以影视解说或长视频解说为默认场景。
- 首期只支持三类 Vlog：
  - 宠物 Vlog；
  - 个人生活 Vlog；
  - 探店 Vlog。
- 用户可以提供抖音、B站等平台的视频链接作为参考；首期只处理用户上传的参考文件，或无需登录且用户有权使用的公开内容。不得绕过下载/登录/平台限制；读取失败时由用户上传其有权使用的文件。
- 用户也可以上传本地视频文件作为参考。
- 参考视频用于理解剪辑风格、节奏和结构，不要求每次创建项目都重新提供。

### 2.2 长期风格

- 系统需要支持长期保存的风格档案 `StyleProfile`。
- 长期风格只作用于用户明确指定的长期任务，不作为账户全局默认风格自动应用。
- 一个用户可以创建多个长期任务，例如“宠物周更”“个人生活月记”或“固定探店系列”，每个长期任务独立绑定一个风格档案及其版本。
- 长期任务下新建的剪辑任务默认继承已绑定风格；一次性任务只有在用户主动选择时才使用长期风格。
- 参考视频是创建或校准风格的可选入口，不是每次剪辑的必填项。
- 长期风格建立完成后，后续任务无需重复添加参考视频。
- 每次开始剪辑时保存风格版本快照，避免长期风格后续修改影响历史任务。
- 风格可以来自：
  - 用户手工配置；
  - 一条或多条参考视频；
  - 用户满意的历史成片。
- 长期风格至少应覆盖：
  - 叙事结构与开头钩子；
  - 镜头节奏、平均镜头时长和快切比例；
  - 横竖屏、裁切和运镜倾向；
  - 字幕样式、位置、动画和密度；
  - 转场类型、频率和持续时间；
  - 滤镜、调色和整体画面倾向；
  - BGM 类型、卡点强度和原声保留比例；
  - 旁白声线、语速、情绪和密度；
  - 输出时长、分辨率和平台规格；
  - 允许使用图片/视频生成补素材的条件和风格。

### 2.3 手机端

- 手机上传入口是部署到 Cloudflare 的 Vue H5；不使用 Taro 或 React Native。现有 Tauri 2（iOS/Android）壳保留为可选的原生增强载体，与 H5 共用上传协议和界面代码，但用户无需安装 App 才能上传。
- **手机端只承担素材上传**：添加、删除及切换已配对 Key，选择相册/拍摄素材，查看队列和续传状态；不提供剪辑、风格编辑、任务编排、审核、成片查看或下载。
- 桌面 Web 为项目创建多个上传 Key。每个 Key 只绑定一个项目和该项目内唯一的素材目录（目录显示名、稳定 `targetId` 与受控相对路径）；一个 Key 永远不能写入其他项目、分类或目录。
- 手机上输入 Key 时执行一次性配对兑换：H5 生成不可导出的 WebCrypto 设备密钥，Mac 在线校验 Key 并写入该手机公钥。兑换成功后浏览器只保存被配对的目录绑定与不可导出的私钥句柄，**立即清除原始 Key**；清除站点数据或换设备需重新输入 Key。用户可在多个已配对 Key 目录之间切换，切换仅影响后续新文件，队列中已有文件永远固定原目标。
- 剪映自动化、任务编排、多 Agent 审查和成片查看/下载只在当前 Mac 的本机 Web 中执行。桌面 Web 与手机上传 H5 只复用领域契约和必要的上传组件，不追求功能对等。
- H5 静态资源可以经 Cloudflare 分发，但项目/目录、Key 明文、素材内容、SQLite 与成片不会上传或托管到 Cloudflare；Worker 只转发有时效的配对、控制及 SDP/ICE 帧。正式实现须先通过 iOS/Android 浏览器的 WebRTC、后台恢复和相册权限 PoC。
- 同时支持 iOS 和 Android；H5 需要支持从相册选择多个视频或图片、拍摄后直接上传、传输进度、断线重试/断点续传及查看素材入库状态。

### 2.4 PC 端

- 首期宿主系统只支持用户当前的 macOS，不适配 Windows 或 Linux。
- 产品的业务界面只使用 Web，不开发 Electron 等独立桌面业务界面。
- 前端 Web、后端 Server、数据库、素材库、媒体 AI 服务和任务调度均安装并运行在本机 macOS。
- 本机安装包负责启动后台服务并打开本机 Web 地址；剪映 Runner 作为当前登录图形会话中的原生后台组件运行。
- PC Web 用于：
  - 项目管理；
  - 素材管理；
  - 参考视频管理；
  - 长期风格管理；
  - 剪辑任务创建、状态查看、最终成片查看和下载；
  - 声音档案及生成能力管理；
  - 成片查看和下载。

### 2.5 公网素材传输

- 手机必须能从外网传输素材，不限定与 PC 位于同一局域网。
- 传输能力需要使用 WebRTC 技术。
- 素材目标是本机 Server 管理的“项目/素材分类”，不是用户手工选择的普通文件夹。
- WebRTC 接收端是本机 Server 内的素材接收服务，不是 PC 浏览器或云端素材网关。
- 应用不向公网持久化项目正文、素材、成片、声音样本或本地数据库；信令/TURN 服务仍会按自身规则处理必要的 WSS 信令、IP/端口、会话时间、ICE 候选和流量计费元数据。
- 公网信令与在线状态确定使用 Cloudflare Workers + Durable Object，并使用 `*.workers.dev` 地址；首期不租 VPS、不购买自定义域名、不部署云端数据库或对象存储。
- 手机只与本机 Server 点对点传输；首期仅 STUN 协助直连，普通直连失败返回 `CONNECTION_FAILED`，不经 TURN 中继素材流量。
- 中继策略由 Provider Adapter 统一判定并固定为拒绝。经 2026-07-31 官方文档复核，独立使用 Cloudflare Realtime TURN 按实时 GB 计费；只有与 Cloudflare SFU 一同使用时免费。SFU 会使媒体经过云端，违背本项目边界，因此首期不配置 TURN 凭据。手机先 STUN 直连；只有配置边界显式收到 `turn:`、`turns:` 或带账号密码的 relay 配置时，才在创建连接前向手机与本机 Web 返回 `TURN_BILLING_REQUIRED`；禁止用户确认付费继续、自动升级或任何付费中继回退。
- 手机上传队列必须持久化 `uploadId`、文件指纹、目标项目/分类、分块位图和已确认偏移。本机离线、切网、切到后台或 App 被系统终止后，手机只能在前台或获得系统允许的后台执行时间内自动续传；其他情形在用户下次打开 App 后续传，不设置云端素材收件箱。
- 上传采用 `queued → transferring → staged → hash_verified → committed → ready` 状态机。只有 `ready` 素材可被整理器、分析器和剪辑任务读取。
- 分块暂存、完整性校验与最终文件提交必须发生在目标素材盘同一卷的暂存目录；校验和持久化完成后才可原子提交正式素材，再由 SQLite 事务创建逻辑素材引用。
- 每个上传必须有持久化 `UploadManifest`，至少保存 `uploadId`、目标项目/分类、预期大小与 SHA-256、分块位图、暂存/目标路径、提交阶段和逻辑引用 ID。不能只以目录扫描结果判断上传是否完成。
- 提交顺序固定为：写入并同步暂存文件 → 校验完整哈希 → 同卷原子改名并同步目录 → SQLite 事务建立逻辑引用并更新 manifest。Server 重启后必须联合 SQLite、manifest 和文件哈希恢复：继续上传、回退到暂存重校验，或保留待诊断状态；不得把候选文件当作普通孤儿直接清理。

### 2.6 素材整理

- 系统需要定期整理素材。
- 素材整理不依赖图片生成、视频生成或大模型能力，未配置 AI 时仍应正常运行。
- 素材库根目录可以在系统设置中修改，首期只设置一个当前生效的素材库根目录。
- 素材库允许设置到 Mac 内置磁盘或外置硬盘；数据库、配置、设备密钥和任务索引始终保留在 Mac 内置磁盘。
- 素材库配置必须持久化并校验卷 UUID、文件系统类型和规范化后的根路径；卷身份或文件系统不匹配即为 `STORAGE_UNAVAILABLE`，不得依路径名称猜测为原磁盘。
- 外置硬盘断开时，相关素材标记为“存储设备离线”，上传、分析和剪辑任务暂停，不得静默改写到内置磁盘的同名目录。
- 修改素材库根目录需要执行受控迁移：复制并校验完成后再切换，旧目录由用户确认后清理，不能直接移动后立即删除源文件。
- 系统需要持续监控当前素材盘容量，并采用两级预警：
  - 警告：剩余空间低于磁盘容量的 10% 或 50 GB，两者取较大值；提示清理、迁移或更换磁盘；
  - 严重：剩余空间低于磁盘容量的 5% 或 20 GB，两者取较大值；停止接收新素材和启动新的生成/剪辑任务，但仍允许清理和迁移。
- 启动剪辑任务前需要估算素材、代理文件、缓存和导出文件所需空间；预计会触发严重阈值时不得启动任务。
- 上传和任务启动时分别为素材盘、系统盘和剪映缓存盘预留可释放的容量配额；预留失败或运行中 I/O 中断时，使用 `STORAGE_UNAVAILABLE` 或 `IO_INTERRUPTED` 作为失败原因码并保留恢复上下文；剪辑任务终态仍按 `BLOCKED_TECHNICAL` 等统一状态机处理。
- 首期不提供应用内自动备份，不自动复制到另一块硬盘、NAS 或云存储；用户如需备份，应自行使用 Time Machine 或其他外部备份工具。
- 采用三级整理计划：
  - 入库即时整理：校验 SHA-256、文件大小和媒体基础信息，生成缩略图/关键帧，并记录项目、素材分类、来源设备和拍摄时间；
  - 每日增量整理：检查未完成上传、孤立文件、精确重复文件、失效代理文件和可重新生成的派生文件；
  - 每周深度整理：识别近似重复、连拍、相似镜头、长期未使用素材和归档候选，并生成整理报告。
- 精确重复采用“一个物理文件、多个逻辑素材引用”：
  - 上传时以 SHA-256 为主键进行判定，并用文件大小、时长和媒体信息再次校验；
  - 已存在相同原文件时，不重复保存第二份物理文件，只为目标项目/素材分类建立新的逻辑引用；
  - 对历史遗留的多份精确重复文件，先合并引用并标记清理候选；原始素材的冗余物理副本只有在用户确认后才可移入回收站。
- 近似重复采用关键帧感知哈希、时长/分辨率特征和音频指纹辅助识别：
  - 只建立相似素材组并推荐最佳版本；
  - 不因近似重复而自动删除任何原始素材；
  - 用户确认后才可批量移入回收站。
- 删除和恢复规则：
  - 原始照片、原始视频和原始录音不得被系统直接永久删除；
  - 用户主动删除、用户确认清理或历史精确重复合并产生的冗余文件统一进入回收站；
  - 回收站默认保留 30 天，期间可恢复；原始素材到期后标记为“待永久删除”并通知用户，仍须再次由用户确认才能永久删除；
  - 上传临时分块、失败任务缓存、可重新生成的缩略图/代理文件可以自动清理；
  - 存储空间不足时，优先清理缓存和派生文件，再提示用户处理原始素材。
- 长期未使用素材只标记为归档候选，不自动删除：默认连续 90 天未使用且未被活跃任务引用时进入候选列表。
- 默认允许通用场景、宠物、食物和店铺内容标签；人脸身份识别、精确位置和其他敏感标签默认关闭，必须由用户主动授权。
- 每次合并、移入回收站、恢复和永久删除都必须记录审计日志；物理文件清理前必须再次确认不存在有效逻辑引用、活跃任务锁或回收站恢复保留。

### 2.7 剪映执行边界

- 不接入现有的 `video-recap` 流程作为核心剪辑能力。
- 不使用 FFmpeg 作为最终成片渲染器。
- 不以生成或修改剪映草稿 JSON 作为核心剪辑方案。
- 首期使用安装在当前 macOS 上的官方剪映专业版，不使用 CapCut Web 或云端 Windows 工作机。
- UI-TARS 是首期唯一的候选 GUI Agent 底座；本机剪映路线只有在通过独立 PoC 验收后才可作为正式实现冻结。
- 通过 PoC 前，`Jianying Operator Skill` 只能用于验证，不得被表述为已验证的全自动出片能力。
- `Jianying Runner` 必须在当前登录的 macOS 图形会话中实际操作剪映界面；任务只允许在单一主显示器、固定分辨率/缩放、固定 UI 语言和固定剪映窗口布局下运行。
- Runner 领取任务前必须通过预检：macOS 未锁屏、无屏保、显示器未休眠、辅助功能与屏幕录制权限有效、剪映前台且已登录、素材盘可用、无更新/付费/未知对话框。
- 每个任务必须保存静态兼容性指纹：macOS 版本/硬件、剪映版本/构建号、UI-TARS 版本或 commit、模型及参数、`Jianying Operator Skill`/系统提示词哈希、Runner 配置版本、显示器参数、剪映布局和 UI 语言。静态指纹变化后进入“兼容性待验证”，按变更级别运行回归后才能恢复正式任务资格。
- 磁盘可用空间、任务路径是否存在、窗口位置能否恢复、是否锁屏和未知弹窗属于每次任务的动态预检，不纳入静态兼容性指纹；动态预检失败只阻断当前任务，不触发不可能完成的全量回归。
- UI-TARS 只能提出状态限定的类型化候选操作，不能提交任意快捷键、文本粘贴或裸坐标点击。原生 `Action Gateway` 必须在每次输入前验证前台 PID/bundle ID、窗口、显示器、最新界面证据、`runId + leaseEpoch`、动作前后置断言和允许的规范化路径；只可将操作放行到剪映及受允许的系统文件选择器。每次放行或拒绝均记录应用、窗口、路径、坐标、证据和决策。越界候选操作一律拒绝并进入 `BLOCKED_TECHNICAL`。
- PoC 和正式运行使用独立的标准 macOS 用户，不授予管理员权限；Runner 环境不得保留可被 Agent 操作的终端、浏览器或系统设置会话。
- 最终预览和导出应由本机剪映专业版完成。
- FFmpeg/ffprobe 如果保留，只能用于缩略图、代理文件、音频提取、素材分析或结果校验，不参与最终剪辑和成片渲染。
- 剪映登录和 macOS 权限应在首次配置时完成；运行中遇到验证码、强制更新、付费素材、焦点丢失或无法安全识别的弹窗时，任务标记为 `BLOCKED_TECHNICAL` 并停止，不能把它变成正常剪辑过程中的人工审核点。
- Runner 只能向剪映、受允许的系统文件选择器和任务目录输入；未知应用、终端、浏览器、系统设置、付款确认和原始素材删除一律停止操作。

### 2.8 图片与视频生成

- 图片生成用于辅助剪辑。
- 视频生成用于辅助剪辑。
- 图片或视频生成能力没有配置时不启用、不展示为可用能力，也不能被剪辑规划器选择。
- 图片和视频生成采用可插拔 Provider，由用户自行配置；首期不内置必须启用的默认服务商。
- 默认不得将素材、音频、参考帧、提示词或剪映截图发送至本机以外。启用任意云端图片/视频 Provider 前，必须单独展示数据类型、目的地、用途、保留/删除规则，并取得显式授权；关闭后剪辑规划器不得再次选择该 Provider。
- 生成结果由系统自动完成内容与技术质量检查，通过后作为普通素材进入素材库，记录来源、生成模型、提示词和生成时间，然后自动参与剪辑，不增加人工确认点。

### 2.9 TTS 与声音克隆

- 系统需要 TTS 能力。
- TTS 和声音克隆采用本机推理优先策略，默认不把声音样本发送给云端服务。
- 本机推理服务作为媒体处理节点运行，PC 的产品交互仍然只通过 Web 完成，不增加独立的 PC 客户端界面。
- 只有在用户主动配置并启用云端 Provider 后，才允许云端 TTS 作为可选降级路径；启用前须单独说明会外发的声音样本、文本、音频片段或特征，以及处理目的、服务商、保留/删除规则，取得显式授权。任何云端 UI-TARS/视觉推理也遵循同一规则。
- 固定旁白和原片人物声线均只能使用具有有效、未撤销授权记录的 Voice ID；身份不明人物、未成年人或授权失效的声音必须在规划阶段阻断克隆调用。
- 如果本机资源不足且未配置云端 Provider，需要明确提示该能力当前不可用，不能静默上传声音样本。
- 同时支持两类声音克隆：
  - 固定旁白声线：长期复用用户授权的旁白声音；
  - 原片人物声线：用于翻译配音或局部对白重制。
- 声音生成结果作为音频素材交给实际编辑器使用。
- 需要记录声音授权、样本来源、Voice ID、用途和删除状态。授权记录至少包含说话人、授权方式、用途范围、创建时间、到期时间和撤销时间；授权撤销后立即禁用 Voice ID、取消待执行的克隆任务、删除本地样本/特征，并向已启用的云端 Provider 发起删除请求或记录其保留例外。系统还须维护 Voice ID 派生物索引：已生成音频和含该音频的未发布项目一律标记为不可复用；历史导出成片的删除、隔离或保留例外必须可追溯。

### 2.10 产品使用范围

- 产品定位为本地部署的单用户个人工具，不按传统云端 SaaS 设计首期能力。
- 首期不设计团队空间、成员权限、套餐、计费和多租户隔离。
- 业务数据、素材、声音样本和成片默认只保存在本机；用户显式授权的第三方 Provider 是唯一可向外传输对应任务数据的例外。
- 仍需要基础身份验证、手机设备绑定和公网传输保护，避免本机素材入口被他人使用。

### 2.11 自动化级别

- 正常剪辑任务必须从素材分析、故事线生成、镜头选择、剪映操作、配音、字幕、BGM、转场、预览校验到导出全部自动完成。
- 用户创建任务后，不需要确认故事线、镜头清单、剪辑计划或 15-30 秒试剪。
- 系统在正式导出前自行执行画面、声音、字幕、时长、分辨率和文件完整性检查。
- 人工只在成品生成后进入流程，用于查看最终成片。
- 首次安装时的 macOS 权限授权、剪映登录以及运行中的技术阻塞不属于剪辑内容审核；成功任务的正常流程不得依赖人工接管。
- 自动化只在 Runner 预检通过时开始。任务终态固定为 `SUCCESS`、`FAILED_QA`、`BLOCKED_TECHNICAL` 或 `CANCELLED`；只有 `SUCCESS` 可作为最终成品展示。
- GUI 执行状态固定为 `PRECHECK → IMPORT → ASSEMBLE → AUDIO_SUBTITLE → PREVIEW_QA → EXPORT → EXPORT_QA → SUCCESS`。每一状态必须有截图、文件或媒体检测证据；状态未知时不得盲目重放点击，必须创建干净工程并从持久化剪辑计划重建。
- 每个 GUI 状态均须定义动作前置条件、状态超时、最大操作数、有限重试次数和退出条件；超过任一预算必须保留证据并安全停止，不允许无限循环或盲目重试。
- 每次执行尝试必须绑定唯一 `attemptId`、RunManifest、显示器 ExecutionLock 和可过期 lease/fencing token；旧尝试封存后才可新建尝试。导出写入不可复用的尝试目录，先以 `.partial` 完成稳定性检测、哈希和独立 QA，再由 SQLite 事务发布为可见成片，任何失败尝试不得覆盖已有成功版本。
- 自动 QA 至少验证导出文件存在、容器可读取、SHA-256、时长、分辨率、帧率、音轨、静音异常、黑帧/冻结帧、字幕覆盖和剪辑计划一致性；关键项失败即为 `FAILED_QA`。

## 3. 当前推荐方案（尚未全部确认）

本节是基于当前约束形成的推荐实现，不等同于已确认决策。

### 3.1 Web 技术栈

- 本机 Web 确定使用 Vue 3 + Vite，由本机 Server 静态托管并通过浏览器访问；与手机 Tauri 应用复用 UI 和契约。
- 手机端使用 Tauri 2 iOS/Android 壳与 Rust 原生能力插件。
- 本机 API 确定使用 Node.js 22 上的 Hono，负责项目、设备绑定、WebRTC 会话和任务编排。
- 媒体 AI 服务推荐使用 Python，负责参考视频分析、素材理解、TTS、声音克隆和生成 Provider 适配。
- SQLite WAL 存储项目、素材、任务、风格、声音档案和持久化任务队列。
- 只有本机 Server 可以写 SQLite；Python Worker 和 Jianying Runner 仅通过本机 API/IPC 上报事件，禁止直接写数据库。任务领取必须使用可过期 lease/fencing token，所有处理必须幂等。
- Server 启动时必须执行 WAL/完整性检查，并把过期 lease、未完成 manifest 和任务证据目录纳入协调恢复；任一恢复结论都要可审计，不能仅凭 Worker 是否存活判断任务完成。
- 本机文件系统保存原始素材、派生文件和成片，并以 SHA-256 建立物理文件与逻辑素材引用关系。
- 素材库路径由用户在系统设置中选择；外置硬盘推荐使用 APFS，其他文件系统需要在写入、文件名和断电恢复测试通过后再标记为受支持。
- 首期不要求安装 PostgreSQL、Redis/BullMQ、MinIO 或 S3 兼容对象存储。
- macOS 原生 `Jianying Runner` 负责辅助功能授权、屏幕采集、剪映启动和 UI 操作，不能放入 Docker 容器。
- 系统、素材盘和剪映缓存目录都必须纳入容量预检；外置素材盘可用不代表内置盘可用。

### 3.2 WebRTC 公网传输

- 使用 Cloudflare Workers + Durable Object 部署极简公网 WSS 信令服务，只交换设备身份、在线状态和 WebRTC 会话信息。
- 由 `RelayProvider` 评估需要的 NAT 中继；首期不部署自建 coturn，也不启用需要付费的 Cloudflare Realtime TURN。中继一旦需付费即返回 `TURN_BILLING_REQUIRED`；TURN 永不做素材持久化。
- 手机通过 WebRTC DataChannel 把素材和必要的控制请求发送给本机 Server。
- 本机 Server 默认不向公网直接暴露 HTTP API。二维码使用一次性、短时有效的配对挑战；本机确认后把设备密钥存入 macOS Keychain，撤销设备后立即拒绝新会话。
- 每次会话使用短时、目标项目/素材分类受限的上传令牌与一次性 nonce；信令使用 TLS/WSS，TURN 使用短期凭据、每设备并发/流量配额和最小化日志。
- 信令服务维护本机节点在线心跳；手机密钥存放在 iOS Keychain 或 Android Keystore，Mac 保存配对公钥或受保护的会话材料。撤销设备时必须关闭活动会话、拒绝后续 DataChannel，并保留未提交暂存的 manifest 供安全恢复或过期回收。
- 应用层进行分块、背压控制、断点续传、SHA-256 完整性校验、暂存配额和过期回收。必须测试锁屏、切后台、强杀、Wi-Fi/蜂窝切换、Mac 睡眠恢复和 NAT 变化。

### 3.3 参考视频分析

- 将参考视频转换为结构化 `ReferenceStyleProfile`，而不是直接复制参考作品。
- 首期仅接受用户上传的参考文件，或用户有权访问的公开链接；不承诺平台登录、绕过下载限制或保存平台原始视频。
- 参考输入只用于提取结构化风格；参考视频的画面、音频、字幕和片段不得进入最终成片。原文件保存期限仍待用户决定。
- 建议提取：
  - 前三秒钩子；
  - 镜头长度分布；
  - 快切和留白节奏；
  - 字幕、转场、滤镜和调色倾向；
  - BGM 节奏和卡点；
  - 旁白密度；
  - 情绪曲线；
  - 片头和收尾方式。
- 当平台链接因登录、权限或平台限制无法读取时，降级为用户授权或上传参考文件。

### 3.4 长期风格继承

推荐优先级：

`本次任务临时调整 > 用户指定的长期任务风格快照 > 对应 Vlog 类型默认风格 > 系统默认风格`

- 风格推荐采用版本管理。
- 长期任务绑定明确的 `StyleProfile` 版本；子剪辑任务创建时生成不可变快照。
- 一次性任务不自动继承任何长期风格，除非用户主动选择。
- 已开始的剪辑保存风格快照，避免后续修改长期任务风格导致历史任务变化。
- 从成片或人工修改中学习到的变化只生成更新建议，不自动修改长期风格。
- Web 端推荐提供“长期任务”和“风格库”，支持绑定、复制、内部质量校验片段、版本回退；任何短片段不得成为人工确认或导出前阻塞步骤。用户查看成片后的偏好变化只能生成候选建议，须由用户明确确认后才创建新的风格版本；Vlog 类型默认风格不是长期风格档案。

### 3.5 Vlog 首批能力

首批确定覆盖：

- 宠物 Vlog；
- 个人生活 Vlog；
- 探店 Vlog。

建议标准任务流程：

1. 创建一次性任务，或创建/选择一个已绑定长期风格的长期任务。
2. 手机上传素材到项目/素材分类。
3. 可选添加参考链接或参考文件。
4. 分析参考风格和用户素材。
5. 自动生成故事线、镜头选择和剪辑计划。
6. 可选生成缺失的图片或视频素材。
7. 可选生成固定旁白或原片人物克隆配音。
8. 本机 `Jianying Runner` 通过 UI-TARS 实际操作本机剪映专业版。
9. 系统自动执行内部预览和质量检查。
10. 本机剪映自动导出成片并进入项目文件库。
11. 用户在 Web 中查看最终成片。

## 4. 仍需讨论的点

以下仅保留尚未确认的问题。已确认的是本机 macOS、官方剪映 GUI 实际编辑、非草稿 JSON 的产品边界；UI-TARS/Operator 的可交付性仍是 Gate B 候选，只有 PoC 通过才可冻结。

### 4.1 存储与剪辑体验

1. **查看成品后允许怎样修改？**
   - 仅自然语言修改；
   - 是否保留每次修改版本。

2. **是否需要自动发布？**
   - 只下载成片；
   - 发布到抖音/B站；
   - 自动发布失败时的重试和告警方式；
   - 标题、封面、简介和标签是否同时生成。

### 4.2 长期风格与参考素材

3. **风格是否允许自动学习？**
   - 只接受手工修改；
   - 根据用户人工修改生成建议；
   - 在用户确认后升级风格版本；
   - 是否允许对不同 Vlog 类型建立子风格。

4. **参考视频保存策略是什么？**
   - 分析后立即删除原文件；
   - 保留链接和结构化风格；
   - 保留原参考文件以便重新分析；
   - 用户是否可以设置保存期限。

### 4.3 本地 AI 与可选 Provider

5. **本机 TTS 和声音克隆使用哪个推理引擎？**
   - 固定旁白和原片人物是否使用同一引擎；
   - 当前 macOS 硬件的性能基线；
   - 样本时长、生成速度和音质验收标准；
   - Python 本地 Worker 与浏览器 WebGPU 的职责边界。

6. **图片和视频生成接哪些可选 Provider？**
    - 首发只接一个还是支持多个；
    - 成本、并发、分辨率和时长限制；
    - 生成结果的自动质量检查和失败重试标准。

7. **素材理解和参考分析使用本地模型还是云模型？**
    - 成本；
    - 处理速度；
    - 隐私要求；
    - 不同模型不可用时的降级策略。

### 4.4 安全、合规和运行成本

8. **抖音/B站参考链接的使用边界是什么？**
    - 原参考文件的保存期限；
    - 是否提供“分析即删 / 仅保留结构化风格 / 保留原文件”三种 `ReferenceAsset` 策略。

9. **本机数据和设备绑定如何保护？**
    - 本机素材库是否需要文件级加密；
    - 手机设备密钥是否存入 macOS Keychain；
    - 丢失手机后的设备撤销流程；
    - 声音样本、人脸和位置数据如何单独保护与删除。

10. **可选 AI Provider 的成本上限是什么？**
    - 本机 CPU/GPU、内存和磁盘资源限制；
    - 可选云端生成 Provider 的预算；
    - 单个任务的最大素材量、视频时长和重试次数。
