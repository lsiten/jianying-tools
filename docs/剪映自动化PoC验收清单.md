# 剪映自动化 PoC 验收清单

> 文档状态：执行前验收基线
> 版本：v0.3
> 适用范围：macOS 本机剪映专业版 + UI-TARS + Jianying Runner
> 前置关系：通过本清单前，不得把 GUI 自动化路线视为首期已验证实现。

## 1. 目标

验证本机 `Jianying Runner` 能否在无人参与剪辑内容决策的情况下，使用 UI-TARS 实际操作官方剪映专业版，完成宠物、个人生活、探店三类 Vlog 的导入、剪辑、字幕、配音/BGM、导出和技术质量检查。

本 PoC 验证的是“自动化可交付性”，不是审美偏好的最终保证。只有技术验收通过的成片才交给用户查看。

## 2. 静态兼容性基线与动态预检

每轮测试开始前记录并冻结以下**静态兼容性指纹**：

- macOS 版本与硬件型号；
- 剪映专业版版本和构建号；
- UI-TARS 版本或 Git commit；
- 使用的视觉模型、模型版本、参数和推理位置；
- `Jianying Operator Skill`、系统提示词和策略文件的内容哈希；
- Jianying Runner 版本和配置哈希；
- 单一主显示器的分辨率、缩放和 DPR；
- macOS 与剪映 UI 语言；
- 剪映 UI 布局签名。

显示器、剪映、UI-TARS、模型或 Skill 等 GUI 语义相关项变化后，必须执行全量回归；Runner 小范围修复至少执行冒烟集与受影响集，再由结果决定是否扩大回归。素材盘卷身份/路径/空间、锁屏状态、窗口位置能否恢复和未知弹窗属于存储可用性或动态条件，不得作为静态指纹的一部分。

每个任务开始前执行**动态预检**：

- 当前用户已登录 macOS，未锁屏、未切换用户、未触发屏保或显示器休眠；
- 只启用一个主显示器，且参数与兼容性指纹一致；
- 剪映处于前台、已登录且版本匹配；
- 剪映窗口已恢复至标准位置/尺寸，且 UI 布局签名匹配；
- Jianying Runner 的辅助功能和屏幕录制权限有效；
- 素材盘、内置系统盘和剪映缓存目录均有足够空间；
- 没有更新提示、付费提示、验证码、未知对话框或其他应用抢占焦点；
- 任务素材、TTS、生成素材和导出目录均在允许路径内。

任一条件失败，任务必须进入 `BLOCKED_TECHNICAL`，不得尝试猜测点击、切换系统设置或要求用户审核剪辑内容。

## 3. 不可违反的执行边界与 Action Gateway

- 只能通过剪映 UI 导入、编辑、预览和导出；不得由系统直接生成、修改或导入剪映草稿 JSON。
- Runner 只能控制剪映、允许的系统文件选择器和任务目录；不得操作浏览器、终端、系统设置、支付界面或未知应用。
- UI-TARS 只能输出候选动作。每个鼠标、键盘、拖放或文件选择动作都必须先经原生 `Action Gateway` 放行：校验前台 PID/bundle ID、窗口标题/边界、单显示器状态、最新截图/布局证据、动作坐标和规范化后的文件路径。
- Gateway 只接受状态限定的 Typed Action DSL；禁止任意文本、剪贴板粘贴、未登记快捷键和裸坐标点击。每条动作必须含 `stateId`、`attemptId`、`leaseEpoch`、允许参数、前置/后置断言、控件证据与超时，并在执行后验证后置断言。
- Gateway 只允许剪映和受允许的系统文件选择器；文件选择器只允许读取任务目录、写入指定导出目录。任何校验不通过或越界候选动作均拒绝、记录并进入 `BLOCKED_TECHNICAL`。
- 每个 Gateway 输入前还必须确认同显示器唯一 `ExecutionLock`、`runId + leaseEpoch` 与 Server 记录一致且未过期；旧 Runner 或旧 lease 不得继续注入输入。
- PoC 运行在无管理员权限的独立标准 macOS 用户中，不保留可被 Agent 操作的终端、浏览器或系统设置会话。
- UI-TARS 的 `END`、`MAX_LOOP` 或自然语言回复不代表任务成功。
- 每个状态变化和 Gateway 决策都必须留存截图、窗口识别结果、操作日志或文件检测证据；日志至少含应用、窗口、路径、坐标、前置条件和放行/拒绝结论。
- 原始素材在 PoC 期间不可删除；失败任务只能清理临时文件和可重新生成的派生文件。

## 4. 任务状态机与恢复限制

```text
PRECHECK
  → IMPORT
  → ASSEMBLE
  → AUDIO_SUBTITLE
  → PREVIEW_QA
  → EXPORT
  → EXPORT_QA
  → SUCCESS
```

允许的终态只有：

- `SUCCESS`：导出和全部技术 QA 通过；
- `FAILED_QA`：已导出但技术质量检查不通过；
- `BLOCKED_TECHNICAL`：权限、登录、版本、窗口、存储、网络或未知 UI 阻塞；
- `CANCELLED`：用户明确取消。

状态未知时不得在旧工程上盲目续跑。应封存旧 `attemptId`，并在新的隔离工程中从持久化剪辑计划重建。

每个状态必须预先定义动作前置条件、状态超时、最大操作数、有限重试次数和退出条件。超过任何预算时不得无限循环或盲目重放，必须保留证据并安全停止；恢复只能从已验证的检查点开始，否则重建干净工程。

每个尝试必须有非剪映草稿格式的 `RunManifest`：`taskId`、`attemptId`、`runId`、`leaseEpoch`、ClipPlan hash、工程标识、已验证状态、动作序号、唯一导出目标和证据 hash。导出只能写入不可复用的 `taskId/attemptId` 目录，禁止覆盖历史文件；先以 `.partial` 落地，经稳定性检测、哈希和 QA 后才以 SQLite 事务发布为成片。

## 5. 数据集、输入边界与留出集

测试集共 60 个真实素材包，每类 20 个：

| 类型 | 数量 | 必含场景 |
| --- | ---: | --- |
| 宠物 Vlog | 20 | 多镜头宠物活动、室内/室外、原声保留与旁白 |
| 个人生活 Vlog | 20 | 日常片段、人物镜头、照片与视频混合 |
| 探店 Vlog | 20 | 门头、环境、食物特写、口播或旁白、字幕 |

每个素材包必须记录：源文件清单、SHA-256、目标比例、目标时长、是否需要字幕、旁白、BGM 和生成补素材。测试集不得使用用户无法授权的参考片段或声音。

测试包还必须覆盖并记录：文件数量、总时长、单文件大小、编码/封装、帧率、横竖屏混合、HDR/SDR、照片混入、可选 TTS/生成素材和内置/外置素材盘。数值上限、支持编码白名单和拒绝条件必须在首轮运行前冻结为 `InputEnvelope`，超出边界的样本不计入成功率。

60 个任务仅作为开发/校准集：可用于定位和修复，但不能单独证明生产级稳定性。完成校准后，冻结 Runner、Skill、模型、环境、测试顺序和所有样本哈希；再运行独立、未参与调试的留出集。若要宣称单任务成功率至少 98%（95% 单侧置信），留出集至少需要 149 个独立任务且全部成功；否则只能报告观察到的结果，不能作该可靠性声明。

## 6. 单任务必测能力

每个任务至少验证：

1. 创建隔离剪映工程并设置目标画幅。
2. 从任务目录导入全部指定素材，不重复导入。
3. 按剪辑计划选择、排序、裁剪和拼接镜头。
4. 添加需要的旁白、BGM、字幕和已验证的基础转场/滤镜。
5. 自动预览并执行导出。
6. 上传或登记最终成片到本机项目素材库。
7. 生成完整状态日志、截图证据和 QA 报告。

## 7. 导出质量检查与 QA Manifest

`EXPORT_QA` 至少验证以下项目：

- 剪映导出完成界面或等价证据存在；
- 导出文件存在、非空、SHA-256 已记录，容器可读取；
- 时长、分辨率、帧率和目标规格一致；
- 预期音轨存在，且不存在整段静音、异常音量或音画明显不同步；
- 无黑帧、冻结帧、异常尾帧或无法解码片段；
- 需要字幕的任务满足字幕时间覆盖和文字可见性检查；
- 实际素材数、旁白/BGM、输出时长与剪辑计划一致；
- 任一关键检查失败即标记 `FAILED_QA`，不得展示为完成成品。

可以使用 `ffprobe`、OCR、抽帧和音频分析做验收；它们只用于检查，不参与最终渲染。

每个测试包必须随附不可变 `QAManifest`：计划时长/分辨率/帧率/音轨、源媒体哈希、预期镜头/音频/字幕时间线及容忍范围、允许的黑场/静音/静帧区间、抽帧时间点、阈值版本和基准素材映射。QA Worker 必须独立于 Planner/Operator；报告输出实际数值、触发阈值、工具版本和失败证据。先以含已知错序、黑帧、静音、错字幕的盲测 fixture 验证 Oracle 全部检出，再进入留出集。除“`SUCCESS` 的 QA 必须通过”外，另行报告一次通过率、恢复后通过率、`FAILED_QA` 率和 `BLOCKED_TECHNICAL` 率，避免以终态定义掩盖质量问题。

## 8. 故障注入与恢复测试

除 60 个正常任务外，至少验证以下场景：

| 场景 | 预期结果 |
| --- | --- |
| 手机切后台、锁屏、强杀、切换 Wi-Fi/蜂窝 | 上传队列不丢失；只有在系统允许或用户下次打开 App 后恢复，不能承诺被杀后自动唤醒。 |
| Mac 睡眠/恢复或屏幕锁定 | Runner 不继续点击；任务进入 `BLOCKED_TECHNICAL` 或可验证恢复状态。 |
| 外置素材盘在上传、分析、导出中断开 | 无静默写入内置盘；任务保留恢复上下文并进入可解释失败状态。 |
| 剪映更新、验证码、付费提示、未知弹窗 | 不点击确认，不导出，进入 `BLOCKED_TECHNICAL`。 |
| Runner 或剪映崩溃 | 不重复导入、不重复加字幕、不重复发布；从干净工程重建或明确失败。 |
| 网络受限、TURN 中继、NAT 变化 | 已绑定设备可安全重连；未授权设备无法建立上传会话。 |

故障测试必须按“故障 × 状态”记录，至少覆盖 `PRECHECK`、`IMPORT`、`ASSEMBLE`、`AUDIO_SUBTITLE`、`EXPORT` 和 `EXPORT_QA` 中的 Runner/剪映崩溃、窗口焦点丢失、空间耗尽、外置盘移除和未知弹窗。每个单元格都要写明注入方式、证据、预期终态、恢复入口和是否允许重建工程。

## 9. 分层通过门槛

### 9.1 可行性 Gate

60 个校准任务满足以下条件，只说明“路线值得继续投入”，不冻结生产执行路线：

- 60 个正常任务中，至少 54 个 `SUCCESS`；
- 三类 Vlog 各至少 18 个 `SUCCESS`；
- 60 个正常任务中，零人工接管、零剪辑内容确认；
- 零次 Action Gateway 放行允许范围以外的应用或路径；
- 零次直接读写剪映草稿 JSON；
- 全部 `SUCCESS` 任务的导出 QA 通过；
- 所有异常测试均产生可解释终态，不出现丢失原始素材、半提交素材或误展示为成功。

同时记录总耗时、P50/P95 耗时、平均重试次数、失败类型分布和每个状态的失败率；这些数据用于冻结留出集协议。

### 9.2 路线冻结 Gate

只有在校准结论通过、配置冻结、独立留出集运行完成且预先声明的可靠性/质量/安全阈值全部满足后，才可冻结 GUI 自动化路线。留出集开始前必须哈希冻结统计协议：样本清单/顺序/随机种子、类型与 InputEnvelope 配额、环境、成功定义与分母、首轮/恢复成功计数、`BLOCKED_TECHNICAL` 计数、最小样本量、单侧置信目标、故障矩阵和 No-Go 条件。留出集必须包含冷启动、连续任务、随机顺序和跨日运行；任一失败不得回流修改后混入原留出结果。

## 10. Go / No-Go 结论

只有同时满足相应 Gate 的前提才可 `Go`：

- 通过第 9 节对应 Gate 的全部硬门槛；
- 兼容性指纹、操作日志、截图和 QA 报告完整可追溯；
- 已确认没有绕过剪映 UI 的草稿文件操作；
- 所有 `BLOCKED_TECHNICAL` 任务均安全停止，且无原始素材丢失。

可行性 Gate 未通过即为 `No-Go`：保留问题、修复 Runner/Skill/环境后重跑受影响校准集。路线冻结 Gate 未通过时不得把 UI-TARS 路线宣称为可交付首期能力；修改后必须使用新的、独立的留出集重新验证。

## 11. 结果记录模板

每次 PoC 记录至少包含：

- 测试日期、操作者、兼容性指纹；
- 测试集版本、校准/留出集标识、冻结配置和每个素材包 ID；
- 每个任务的状态时间线、重试次数和最终状态；
- 导出文件路径、SHA-256、媒体 QA 结果；
- 截图和日志目录；
- 异常场景结果；
- Gateway 放行/拒绝记录、动作预算消耗和 QA Manifest；
- `Go` / `No-Go` 结论及阻断问题。
