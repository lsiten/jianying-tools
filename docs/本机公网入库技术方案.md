# 本机公网入库技术方案

> 文档状态：已实施的公网传输基线；Cloudflare TURN 长期凭据仅保存在 Worker Secret
> 版本：v0.7
> 范围：iOS/Android 手机 → WebRTC → 用户本机 macOS Server → 项目/素材分类
> 不含范围：剪映 GUI 自动化、云端素材存储、应用内自动备份

## 1. 设计目标

在 Mac 不对公网开放 HTTP 端口的前提下，让已配对的 iOS/Android 手机把素材传给本机指定的项目/素材分类。公网设施默认只参与会话协商；当 NAT 或运营商网络无法建立点对点路径时，已配置的 Cloudflare TURN 才中继加密 WebRTC 字节。Workers 不转发或保存素材，TURN 也不持久化素材。

本设计以“最终文件、SQLite 逻辑引用、入库状态三者绝不相互矛盾”为首要目标；传输速度和后台持续能力不能突破移动操作系统许可边界。

## 2. 组件与信任边界

| 组件 | 运行位置 | 职责 | 不负责 |
| --- | --- | --- | --- |
| Tauri 2 iOS/Android App（Vue WebView + Rust 插件） | 用户手机 | 选择素材、持久化上传队列、分块传输、显示状态 | 云端缓存素材、决定本机文件路径 |
| 本机 Server | 用户 Mac | 配对、会话授权、WebRTC 接收、manifest、入库提交、任务可见性 | 向公网开放素材 HTTP 接口 |
| 本机素材盘 | 用户 Mac/外置盘 | 暂存、校验、原始素材与派生文件 | 保存密钥、承担数据库事务 |
| 信令服务 | Cloudflare Workers + Durable Object | WSS 会话协商、Mac 在线状态转发 | 保存素材、长期保存业务内容 |
| Cloudflare STUN / TURN | 公网 | NAT 探测、点对点协商和必要时的临时中继 | 解密、落盘、分析或长期保存素材 |

本机 Server、手机和公网信令均通过主动建立的 TLS/WSS 连接协作，因此不依赖家庭宽带公网 IP 或端口映射。当前部署使用 `upload.lene.fun`，不部署 VPS。Mac 不在线时，手机保留本地队列，信令服务不接收素材。

## 3. 设备配对与会话授权

### 3.1 一次性配对

1. Web 端在本机 Server 上创建一次性、短时有效的配对挑战，并显示本机公钥和签名挑战的二维码。
2. 手机扫描后，通过 WSS 将设备公钥、设备私钥签名的挑战响应和必要设备信息发送给本机 Server。
3. 本机 Server 在本地 Web 上显示待确认设备；用户确认后，将配对公钥和设备状态写入本机安全存储。
4. 手机私钥只保留在 iOS Keychain / Android Keystore；配对成功后二维码、挑战和 nonce 立即失效。

首次配对需要用户确认；正常上传不再要求逐次人工确认。设备撤销由本机 Web 发起，立即使配对记录、上传 grant 与活动会话失效。TURN 长期 Key ID 与 API Token 只保存在 Cloudflare Worker Secret，不能进入本机、H5、日志或项目文件。

### 3.2 一次上传会话

1. 手机选择项目、素材分类和文件，先在本地队列生成 `uploadId` 与文件指纹。
2. 手机经 WSS 查询本机节点是否在线；在线时向本机 Server 申请仅限该 `uploadId`、项目/分类、文件大小、SHA-256、设备和有效期的上传 grant。
3. 本机服务在创建每个上传会话前，优先准备 STUN；通过已有信令 HMAC 向 Worker 的受认证 TURN 路由请求短期 `username` / `credential` 和 TURN URL。Worker 使用其 Secret 中的长期 Cloudflare 值调用 `generate-ice-servers`。相同的临时 ICE 配置同时用于 Mac 的 node-datachannel peer 与手机浏览器 peer。浏览器不可用的 `:53` 候选会被过滤；长期 Key ID/API Token 永不下发。
4. 若浏览器在建立 WebRTC 时得到 `CONNECTION_FAILED` 或 `SIGNALING_TIMED_OUT`，H5 不更换文件或目录，直接以同一 `uploadId` 自动申请一次 resume 会话；本机为该会话生成新的短期 ICE 凭据，客户端从已持久化 ACK 偏移续传。协议/完整性拒绝及第二次连接失败不会被伪装成成功，而是保留为可恢复队列。
5. 上传 grant 还绑定一次性 `jti` 和客户端 DTLS fingerprint。本机 Server 先在 DataChannel 内验证设备签名、grant 与 DTLS fingerprint，才创建或恢复 manifest；之后只接受令牌、设备、目标项目/分类、文件哈希与分块序号全部一致的数据帧。
6. Server 返回持久化确认偏移与分块位图；手机以此续传，而不以“已发送”判断成功。

令牌必须短时有效、一次会话绑定、可撤销、不可跨项目/分类复用。对重放 nonce、过期令牌、设备/DTLS 指纹不匹配或不一致元数据一律拒绝并记录安全审计事件。

## 4. 传输与提交协议

### 4.1 数据帧与背压

每个分块消息至少携带 `uploadId`、chunk 序号、offset、长度、分块校验值和有效令牌标识。控制消息与文件分块分通道或有明确消息类型，包含：`resume`、`ack`、`nack`、`pause`、`cancel`、`complete`。

本机 Server 根据素材盘可用空间、暂存配额、写盘速率和 DataChannel 缓冲状态返回背压；手机收到 `pause` 后持久化进度并等待恢复，不在内存中无限堆积分块。

每个分块的确认顺序固定为：范围/摘要验证 → 写入指定 offset → 同步文件内容 → 持久化 manifest 位图和单调 `ackEpoch` → 同步 manifest → 返回 `ack(ackEpoch, bitmapDigest)`。手机重启或恢复时仅承认已收到的持久化 `ackEpoch`；Gate A 必须在该序列每个边界强杀 Server 验证不丢块、不误确认。

### 4.2 状态机

```text
手机队列：queued → connecting → transferring → waiting_resume → completed | cancelled | failed

本机入库：queued → transferring → staged → hash_verified → committed → ready
                                          ↘ recoverable_error / rejected
```

手机“completed”只表示本机已确认进入 `ready` 或建立了同 SHA-256 的逻辑引用；`staged`、`hash_verified`、`committed` 都不向整理器、分析器或剪辑任务暴露。

### 4.3 原子提交

本机 Server 为每个上传维护 `UploadManifest`。文件写入、校验和最终提交必须在目标素材盘同一卷内完成：

1. 写入暂存文件并同步文件内容；
2. 校验预期大小和完整 SHA-256；
3. 同卷原子改名到受控正式路径并同步所在目录；
4. 在 SQLite 事务中创建或复用物理 blob，建立项目/分类逻辑引用，更新 manifest 为 `ready`。

相同 SHA-256 只保留一个物理 blob；每个项目/素材分类获得独立逻辑引用。任何步骤崩溃后均以 manifest、文件、哈希和 SQLite 对账恢复，绝不由目录扫描直接推断 `ready`。

## 5. 存储、可用性与恢复

- 配置素材根目录时记录卷 UUID、文件系统类型、规范化根路径和 APFS 设备标识；外置盘按卷身份而非挂载名识别。拒绝 `..`、符号链接或位于受控根目录外的暂存/目标路径。
- 预留素材盘的完整文件/暂存容量，同时预留系统盘与剪映缓存盘的代理和导出容量；预留失败即拒绝新上传或新任务。
- 外置盘离线、文件系统不匹配或写入中断时，以 `STORAGE_UNAVAILABLE` / `IO_INTERRUPTED` 原因码暂停；不得转写到内置盘同名目录。
- Server 重启时先检查 SQLite WAL/完整性，再扫描未终态 manifest：核对物理文件与哈希、补全缺失引用或回退可继续状态。无法证明一致性的对象进入待诊断，不自动删除。
- 临时分块只在 manifest 已过期、没有 SQLite 引用、没有活跃 lease 且审计记录完整时才可清理。

## 6. 安全与运行约束

- 仅已配对手机可申请上传会话；设备撤销立即关闭其活动 DataChannel 并使 grant 失效。配置 TURN 时，本机仅用已有信令 HMAC 向 Worker 请求会话级短期凭据。
- 本机节点经 WSS 心跳公开“在线/离线”而非素材目录或项目内容；云服务仍会处理必要的 WSS 信令、IP/端口和会话时间元数据。首次配对必须显示这一最小外发清单及服务商保留规则。
- 手机端明确展示“等待 Mac 在线”“连接失败，请更换网络后重试”“等待用户打开 App 续传”等状态；不承诺 iOS/Android 在被系统终止后自动恢复。
- 首期不设单文件大小、单批次大小或单批次文件数量的人为上限。`InputEnvelope` 只冻结分块大小、可靠/有序 DataChannel 参数、最大分块内存、支持 MIME/编码、会话 TTL、最大恢复次数和网络超时；文件能否继续由实际素材盘可用空间、暂存/恢复状态和完整性校验决定，而非业务大小阈值。
- Cloudflare Workers + Durable Object 是已确认的信令服务。Cloudflare Realtime TURN 的独立使用按实时 GB 计费；已订阅账户把长期 TURN Key/API Token 写入 Worker Secret 后启用。本机不保存长期值。验收应覆盖真实运营商、Wi-Fi、蜂窝、UDP 受限和仅 TCP/TLS 网络，并记录中继实际启用情况。

### 6.1 Worker TURN 配置

Cloudflare Dashboard 创建的长期值只写入 Worker Secret；禁止写入本机环境、macOS 钥匙串、仓库或 H5：

```text
TURN_KEY_ID=<Cloudflare TURN key id>
TURN_API_TOKEN=<Cloudflare TURN credential-generation API token>
```

`TURN_KEY_ID` 与 `TURN_API_TOKEN` 必须同时作为 Worker Secret 存在。首次已配对后，本机自动使用 `https://upload.lene.fun`、`stun:stun.cloudflare.com:3478` 和 86400 秒短期凭据策略；可用非敏感环境变量 `JIANYING_TURN_CREDENTIAL_TTL_SECONDS` 覆盖 TTL。本机不施加 TTL 上限。若会话过期或连接失败，H5 自动申请一次 resume 会话，由 Worker 签发新的短期凭据。TTL 只限定短期 relay 凭据，不限制文件大小、批次大小或文件数量。

## 7. Gate A 实施顺序

1. 先实现本机 manifest、同卷暂存/提交、SQLite 幂等引用和重启对账，不接手机 UI。
2. 加入本机模拟客户端，覆盖重复分块、乱序、重放、磁盘满、进程终止与外置盘断开。
3. 加入 WSS 配对、短时令牌、设备撤销和在线心跳。
4. 接入真实 Tauri 2 iOS/Android 客户端，验证 STUN 优先、已配置 Cloudflare TURN 的 UDP/TCP/TLS 候选，以及短期凭据不泄漏长期 API Token。
5. 以《本机入库可靠性 PoC 验收清单》完成故障矩阵，再允许 `ready` 素材进入后续剪辑 PoC。

## 8. 已确认的上传与 TURN 策略

| 参数 | 当前实现 | 约束 |
| --- | --- | --- |
| 单文件/批次 | 无业务大小、总量或文件数量上限 | 仅真实素材盘容量、操作系统/文件系统能力、I/O 中断和完整性失败会拒绝或暂停。 |
| 并发 | 手机端最多 3 个活动传输，待传队列无长度限制 | 并发是内存、网络与磁盘背压保护，不是批次或文件数量限制；单项失败不阻塞后续项目。 |
| TURN 中继 | Cloudflare Realtime TURN | 本机每个上传会话经 HMAC 请求 Worker；Worker Secret 中的长期值仅用于生成短期 ICE 凭据。 |
| 凭据安全 | 长期凭据仅在 Cloudflare Worker Secret | H5 与本机都只收到短期 TURN 用户名/密码。 |
| 外置素材盘 | 首期仅 APFS | APFS 原子改名、文件名和断电恢复语义最可控；其他文件系统必须通过单独兼容性 PoC 才能启用。 |
| 未完成上传/暂存 | 无活动会话且无恢复进度后保留 7 天，再进入可清理候选 | 不会因文件或批次大小提前清理。 |
