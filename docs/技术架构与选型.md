# 技术架构与选型

> 文档状态：已确定开发基线
> 版本：v1.2
> 更新日期：2026-08-01
> 适用范围：单用户、本机 macOS、iOS/Android 手机、Web 管理端

## 1. 不可变边界

- 业务、数据库、素材、声音样本、成片和默认 AI 均在用户的 Mac 本机；不使用云端数据库、对象存储、VPS 或 Docker。
- PC 端只提供浏览器访问的本机 Web；本机安装器以 `launchd` 启动服务，剪映执行器运行在当前图形登录会话。
- 手机素材从外网经 WebRTC 到本机；Cloudflare 仅承载 WSS 信令/在线状态，不承载素材。
- 原文件没有单文件、批次总量和文件数量的业务上限；入库仅受真实磁盘预留、文件系统、I/O 与完整性约束。
- 剪映专业版负责最终预览和导出；FFmpeg/ffprobe 只作媒体分析、代理、缩略图和导出校验。

## 2. 选型结论

| 层 | 已选技术 | 不选项与原因 |
| --- | --- | --- |
| 工作区 | `pnpm` workspace、TypeScript 5.9、Node.js 22 LTS；Python 使用 `uv` 独立锁定环境 | 不以 Bun 作为正式服务端运行时：WebRTC 服务端原生绑定的 Node 兼容性和诊断生态更稳。 |
| 本机业务服务 | Node.js 22 上的 Hono + Zod + OpenAPI；REST 与本机 WebSocket 控制面 | Node 运行时是为 `node-datachannel` 原生绑定服务，不使用 Bun；不引入 Redis/BullMQ，单机任务、lease、outbox 和审计全部进入 SQLite 事务。 |
| 本机数据 | SQLite WAL + `better-sqlite3` + Drizzle migrations；文件系统为大对象存储 | 不使用 PostgreSQL/云数据库；SQLite 只由 Node/Hono 进程写入。 |
| 桌面 Web | Vue 3 + Vite + Vue Router + Pinia + Vue Query；Mac 由本机 Hono 静态托管并在浏览器访问 | 不再用 Nuxt。桌面 Web 是项目、素材、风格、剪辑任务、多 Agent 审查和成片的唯一操作面；Web 不直接读写素材目录或 SQLite。 |
| 移动上传 H5 | 独立 Vue 3 + Vite H5，Cloudflare Workers Static Assets 部署 | 无安装的公网素材上传入口；只实现 Key 配对、Key 切换、选取/拍摄、上传队列与恢复。H5 不实现剪辑、审核或成片页面，静态托管不含项目/Key/素材数据。 |
| 原生可选壳 | Tauri 2（iOS/Android）+ Rust；自定义 `upload-queue`、`device-keystore` 和媒体选择能力插件 | 与 H5 共用上传协议；仅在需要系统级后台续传、Keychain/Keystore 与媒体权限增强时使用，不是用户进入移动上传的前置条件。 |
| WebRTC | H5 浏览器的 `RTCPeerConnection`/DataChannel（可选 Tauri 原生队列）；Mac 服务端 `node-datachannel`（libdatachannel 绑定） | 不用浏览器 P2P 接收，也不经 HTTP 暴露素材。iOS/Android 浏览器与 `node-datachannel` 的二进制 DataChannel、切后台和恢复必须先通过 Gate A。 |
| 公网控制面 | Cloudflare Workers + Durable Objects Hibernation WebSocket API；Wrangler 部署 | Worker/DO 只转发配对、在线状态、SDP/ICE、撤销事件；不落素材、项目、成片或媒体元数据。 |
| TURN | STUN 优先；本机经 HMAC 向 Worker 请求 Cloudflare Realtime TURN 短期凭据 | 独立 TURN 按实时 GB 计费；长期 Key/API Token 仅作为 Worker Secret 保存，不采用 SFU，不在本机或 H5 保存长期凭据。 |
| 媒体/AI Worker | Python 3.12 + FastAPI（仅 Unix Domain Socket）+ FFmpeg/ffprobe；通过本机受鉴权 RPC 调用 | Python Worker 不直接写 SQLite，不向公网监听端口。 |
| 本机 TTS | CosyVoice 3.0 本地 Provider（Apache-2.0）+ Apple Silicon PyTorch/MPS；Voice 授权与派生物索引由主服务管理 | 未配置或硬件 PoC 不达标时显示能力不可用；不静默上传声音。云端 TTS 是用户显式配置后的独立可选 Provider。 |
| 图片/视频生成 | `GenerationProvider` 插件接口；默认没有 Provider、没有 UI 可用入口 | 不预装或暗中启用任何云服务。授权、数据类型、保留规则和 Provider 配置缺一不可。 |
| 剪映执行器 | Swift 6 原生 `Jianying Runner`：Accessibility API、ScreenCaptureKit、Keychain、`launchd`；UI-TARS 仅生成受限的类型化候选操作 | 不用剪映 JSON 草稿或 FFmpeg 输出最终成片；不允许模型提交裸坐标、任意快捷键、终端命令或系统设置操作。 |
| 质量与交付 | Vitest、Playwright、Xcode 真机测试、Maestro、故障注入；`pkgbuild`/`productbuild` 本机安装包 | 不以 mock、截图或单元测试替代真机、磁盘故障和剪映 GUI 验收。 |

## 3. 运行拓扑与数据边界

架构图见 [本机智能剪辑系统](architecture/本机智能剪辑系统.html)。

### 3.1 本机进程

1. `apps/server` 是唯一写 SQLite 的 Node/Hono 进程，负责项目、素材、风格、任务、设备、审计、存储预留和工作流 lease。
2. `apps/client` 的桌面入口是 Vue 3/Vite 本机 Web；它是项目、素材、上传 Key、风格、剪辑任务、审查与成片查看的唯一管理界面，只经 OpenAPI 调用 server，素材预览由 server 签发短时本机访问能力。
3. `apps/mobile-upload` 是独立部署的 Vue H5：用户添加一次性 Key，获得一个目录级的已配对绑定，在多个绑定之间切换后上传。H5 仅把有时效的控制消息经 Worker 路由到在线 Mac，素材字节仍只在浏览器 DataChannel 与 Mac 间流动。
4. `apps/mobile-upload` 的 H5 只持久化已配对目录、设备私钥和未完成上传的 `uploadId`/文件指纹，不持久化原始 Key 或文件字节；刷新后用户重新选择同一文件，完成 SHA-256 校验后从服务端持久 ACK 的 offset 继续。`apps/mobile-shell` 是后续可选的 iOS/Android Tauri 2 原生壳，可在系统级后台续传场景持久化队列与分块位图；两者均不包含剪映控制或成片界面。
5. `workers/signaling` 是唯一公网组件，按一个本机节点一个 Durable Object 会话路由 WSS 消息、分发移动上传 H5 静态资产，并代本机 HMAC 认证请求生成短期 TURN ICE 配置；不接收 DataChannel 文件字节。
6. `services/media` 是 Python 本机 Worker。只从主服务读取任务输入和写入任务目录，所有状态变化经 RPC 回报给 server。
7. `apps/jianying-runner` 是 Swift 本机进程，运行在登录用户图形会话；通过本机 IPC 领取带 lease/fencing token 的任务。

### 3.2 上传 Key 的目录能力边界

1. 桌面端创建 Key 时必须选择项目与目录显示名；服务端生成 256-bit 随机原始 Key，只在创建成功的桌面界面显示一次，不在 SQLite 中保存明文。
2. SQLite 仅保存 Key 标识、项目/目录目标、经 HMAC-SHA-256 加 pepper 的 Key 校验值、创建/过期/撤销时间与首次兑换状态。每一个 Key 对应唯一稳定 `targetId` 与受控相对目录；文件物理 blob 仍按 SHA-256 去重，目录是逻辑素材引用路径，不破坏去重。
3. H5 的“添加 Key”必须执行在线的一次性兑换与设备公钥登记；不能把 Key 当作长期 HTTP Bearer Token，也不能把 Key、项目名称、素材元数据写入 Cloudflare Durable Object 存储。
4. 每次上传授权都由已配对设备签名，携带其当前 `targetId`；Mac 只为该绑定生成 `uploadId` 和 WebRTC 会话。队列项在创建时冻结 `targetId`，之后 H5 切换 Key 不会重定向已排队或续传的文件。
5. 桌面端可单独撤销或重新生成任一 Key。撤销立即禁止新兑换和新会话，并使该绑定未开始的队列项显示“Key 已撤销”；已经进入本机持久化的素材按既有数据保留策略处理，不自动删除。

### 3.3 素材可靠性协议

手机和本机 Server 的可靠边界固定为：

```text
DataChannel chunk
  -> 范围/令牌/DTLS 指纹/分块哈希验证
  -> 同卷暂存文件指定 offset 写入并 fsync
  -> SQLite manifest + 分块位图 + 单调 ackEpoch 事务
  -> 原子写入 manifest 镜像并同步目录
  -> ack(ackEpoch, bitmapDigest)
```

完成后先验证完整 SHA-256，再同卷原子改名到内容寻址 blob 路径，最后在 SQLite 事务中创建/复用 blob 与项目/分类逻辑引用。`ready` 前的对象不允许进入整理、分析或剪辑任务。重启恢复只按 SQLite、manifest 镜像、暂存文件和哈希共同判断，不能由目录扫描推断成功。

分块序号和偏移均为无符号 64 位协议字段，SQLite 以十进制文本保存，移动队列也以十进制文本保存，不设置单文件、批次总量或文件数量的业务阈值。若当前 Node 文件 API 无法寻址某个协议合法偏移，则返回 `STORAGE_POSITION_UNSUPPORTED` 并保留队列；这是实际运行时/文件系统边界，不会把文件或批次改为产品上限。

### 3.4 TURN 的确定行为

1. 首先使用 STUN 候选；可达时外网传输保持点对点，Cloudflare 不看见素材字节。
2. Server 为每个上传会话创建带节点身份和 5 分钟有效期的 HMAC 控制令牌，调用 Worker `/v1/turn/<nodeId>`；Worker 用 Secret 中的 Cloudflare长期值调用 `generate-ice-servers`，取得短期 `username` / `credential` 与 TURN URL。
3. 服务端将同一份短期 ICE 配置同时用于 node-datachannel PeerConnection 和发给 H5 的会话响应；Cloudflare API Token/长期 Key 不出 Worker Secret，浏览器不可用的 `:53` 候选在发给客户端前移除。
4. H5 在 `CONNECTION_FAILED` 或 `SIGNALING_TIMED_OUT` 后保留同一 `uploadId`，自动请求一次 resume 会话；Server 因而签发新的短期 ICE 凭据，已持久化 ACK 的分块不会重传。第二次失败保留可恢复队列并如实展示错误，不掩盖协议或完整性拒绝。
5. 未部署 Worker TURN Secret 时，凭据请求安全失败并保留可恢复上传；不会将失败伪装为成功，也不经 SFU 或 Workers 持久化素材。

移动端原生 Rust 层持有 session 唯一的 mobile-role WSS 连接：`close(CONNECTION_FAILED)` 路由到准确的 `uploadId` 并写入可恢复的 `Paused(NetworkUnavailable)`，再向 WebView 发终止事件。非终止 SDP/ICE 只以控制事件转交 WebView；素材字节绝不进入 Tauri IPC 或 Worker。一个 session 只能绑定一个 upload，未绑定或 session 不匹配的终止帧没有队列副作用。

授权帧还必须同时通过一次性 grant 校验和实际 DTLS 远端 `sha-256` 证书指纹校验；控制帧中伪造或从另一连接重放的指纹返回 `DTLS_FINGERPRINT_MISMATCH`，在任何素材字节写入前拒绝。

每台已配对手机在其 Keychain/Keystore 中保留 Ed25519 私钥，Mac 的现有 SQLite 状态库只持久化该设备 ID、显示名和 SPKI 公钥。会话在签发信令 token 前要求该设备已配对；控制帧的 `deviceProof` 必须签名绑定设备 ID、会话 ID、上传 ID、一次性 grant 与 DTLS 指纹。任一字段变更、未配对设备或错误密钥均在首个素材字节前拒绝，不依赖云端身份服务。

这意味着受限 NAT 的可达性依赖用户启用的 TURN 服务及其资费/配额；本项目不承诺免费中继，但会在有配置时自动使用会话级短期凭据，并保持素材不落入 Workers。

## 4. 代码仓库结构

```text
apps/
  server/                 Node/Hono 本机业务与 WebRTC 接收器
  client/                 Vue 3 / Vite 共享 PC Web 与 Tauri UI
  mobile-shell/           Tauri 2 iOS / Android 与 Rust 原生能力插件
  jianying-runner/        Swift macOS 受控 GUI 执行器
packages/
  contracts/              Zod/OpenAPI 请求、事件和错误码
  domain/                 不依赖框架的状态机、策略和领域模型
  protocol/               WebRTC DataChannel 帧与 ACK 编解码
  testkit/                故障注入、临时 APFS 卷和场景夹具
workers/
  signaling/              Cloudflare Worker + Durable Object
services/
  media/                  Python 媒体分析、TTS、可选生成 Provider
docs/
```

## 5. 开发顺序与冻结闸门

| Gate | 要交付的证据 | 通过条件 |
| --- | --- | --- |
| A：移动和 WebRTC | Tauri iOS、Tauri Android、macOS 物理设备的直连上传；切网、后台、强杀和恢复记录 | Tauri WebView DataChannel、原生上传队列和 `node-datachannel` 可稳定续传，且 ACK 只在磁盘和 manifest 都持久化后发出。 |
| B：素材库 | SQLite WAL 检查、断电/强杀、APFS 同卷提交、外置盘离线和重复入库故障矩阵 | 无丢块、无误 `ready`、无越根路径、无第二个相同 SHA-256 blob。 |
| C：本机服务与 Web | OpenAPI 合约、浏览器真实操作、设置素材根目录、容量预警 | 桌面 Web 显示素材盘可用空间与未完成上传预留；浏览器不直接持有文件系统/数据库权限，严重容量状态阻断新上传/新任务。 |
| D：剪映 | 固定环境、权限、UI-TARS 受限动作、证据与导出 QA | 未知对话框/焦点丢失/权限失效一律 `BLOCKED_TECHNICAL`，无盲点重放。 |
| E：媒体能力 | CosyVoice 本机声线授权与撤销；未配置生成 Provider 的规划回退 | 默认零外发；授权撤销后不可再生成或复用。 |

## 6. 版本与升级策略

- 初始安装将锁定每个 JavaScript、Python、Swift 和 Worker 依赖的精确版本及完整性哈希；生产升级只能由兼容性清单驱动，不使用浮动 `latest`。
- Node、Tauri、iOS/Android WebView、`node-datachannel`、剪映、UI-TARS、macOS、显示器参数、Runner 策略和模型版本进入兼容性指纹。静态指纹改变后必须重跑对应 Gate，不能直接领取正式剪辑任务。
- Cloudflare 和外部 Provider 的当前价格/条款不作为编译时常量；每次启用都由 Provider Adapter 返回可审计的能力状态。未知即按不可用处理。

## 7. 立即开发范围

先建立上述 workspace 和 `packages/domain`/`packages/contracts`，随后实现 Gate B 的本机可靠入库核心；它是 Web、手机、整理器和剪映任务共同依赖的最底层能力。前一轮 Bun/Hono 草稿不会并入正式架构。

## 8. 选型依据

- [Cloudflare Realtime TURN](https://developers.cloudflare.com/realtime/turn/)：独立 TURN 的计费方式、协议与分配限制。
- [Cloudflare Durable Objects WebSockets](https://developers.cloudflare.com/durable-objects/best-practices/websockets/)：Hibernation WebSocket API 的连接与成本语义。
- [Tauri v2](https://v2.tauri.app/)：iOS、Android 和桌面共享的 Rust/WebView 应用框架。
- [Tauri 插件开发](https://v2.tauri.app/develop/plugins/)：把大文件读取、密钥和系统权限保留在原生层的插件边界。
- [CosyVoice](https://github.com/FunAudioLLM/CosyVoice)：本地多语言零样本声音克隆候选与 Apache-2.0 许可证。
